核心理念

为什么需要 Planning with Files？

AI 代理的致命弱点——以及如何用文件系统来解决。

💾

持久化记忆

TodoWrite 工具在上下文重置后会消失，但文件系统永远不会。重要信息存储在磁盘上，而非volatile 内存中。

🎯

防止目标漂移

50+ 次工具调用后，原始目标会被遗忘。通过自动重新读取计划文件，保持目标始终清晰。

📊

追踪错误

失败不被追踪，相同的错误就会重复。记录所有错误，避免重蹈覆辙。

🧠

上下文工程

上下文窗口就像 RAM（易失性、有限），文件系统就像 Disk（持久化、无限）。把重要内容写到磁盘上。

⚡

96.7% 通过率

在 Anthropic 的 SkillCheck 评估中，使用此模式的通过率从 6.7% 提升到 96.7%。

🔄

会话恢复

运行 /clear 后，技能会自动恢复之前的会话。从上次离开的地方继续工作。

三文件模式

每个复杂任务都需要三个文件

就像 Manus 一样工作——用文件系统作为工作记忆。

📋

Task Plan

task_plan.md

追踪阶段和进度——这是你的主计划文件，包含目标、阶段、决策和错误记录。

  • 任务目标定义
  • 3-7 个阶段（带状态）
  • 重大决策记录
  • 遇到的问题
  • PreTool 钩子自动读取
🔍

Findings

findings.md

存储研究发现——所有研究、探索和资源收集的发现都放在这里。

  • 研究结果
  • 技术决策（含理由）
  • 有用资源 URL
  • 每 2 次查看/搜索后必须更新
  • 替代上下文填充
⚙️

Progress

progress.md

会话日志和测试结果——追踪所有操作、测试结果和错误日志。

  • 操作日志
  • 测试结果
  • 错误日志（含时间戳）
  • 完成阶段总结
  • 重启后的 5 问题检查
5 步快速开始

如何使用 Planning with Files

按照以下步骤，让你的 AI 工作流发生革命性变化。

1

调用 Skill，描述任务 开始

在 Claude Code 或 OpenCode 中输入 /plan 或 /planning，然后描述你要完成的任务。AI 会自动创建三个规划文件。

/plan 构建一个用户认证系统，包含注册、登录、找回密码功能
2

规划阶段 制定计划

在 task_plan.md 中将任务分解为 3-7 个阶段。每个阶段需要明确的状态（pending / in_progress / complete）。

### Phase 1: 需求分析 - [ ] 理解用户需求 - [ ] 设计数据库 schema - **Status:** in_progress
3

工作和记录 迭代执行

工作时更新文件。研究 → findings.md，决策 → findings.md，实现 → progress.md。

发生什么 更新哪个文件
研究某事 findings.md
2次查看/搜索后 必须更新 findings.md
技术决策 findings.md（带理由）
完成阶段 task_plan.md + progress.md
发生错误 task_plan.md + progress.md
4

决策前重新读取 保持专注

Hooks 会自动在 Write/Edit/Bash 操作前读取 task_plan.md。如果没有 hooks，手动在重要决策前重新读取计划。

// 钩子自动完成，但你可以这样手动提醒自己： // "在继续之前，让我重新阅读 task_plan.md 来刷新目标"
5

完成并验证 交付

验证任务完成：检查 task_plan.md 所有阶段是否 complete，progress.md 是否记录了所有操作。

# 使用脚本验证 ./scripts/check-complete.sh # 或者让 Stop Hook 自动检查

可用命令

如何调用 Skill

多种方式启动你的规划会话。

/plan [任务描述]

⭐ 推荐方式（v2.11.0+）

输入 /plan 后描述你的任务，AI 会自动创建三个规划文件。例如：/plan 构建用户认证系统

/plan:status

📊 查看进度（v2.15.0+）

快速查看当前规划状态，一目了然所有阶段和完成情况。随时检查任务进展。

/plan-goal

🎯 目标终止条件（v2.38.0+）

结合 Claude Code 的 /goal 命令，从当前规划派生终止条件。与 /goal 配合使用。

/plan-loop

🔁 规划循环（v2.38.0+）

结合 /loop 命令，默认每 10 分钟重新读取规划文件并运行检查。保持长期任务的专注度。

/planning

🚀 原始启动命令

输入 /planning 找到自动补全，启动原始的规划会话。效果与 /plan 相同。

/plan-attest

🔐 哈希验证（v2.37.0+）

用 SHA-256 锁定 task_plan.md，钩子阻止任何篡改。确保计划文件的完整性和可信度。

关键规则

必须遵守的规则

遵循这些规则，获得最佳效果。

📝

规则 1: 先创建计划（必须）

永远不要在没有创建 task_plan.md 的情况下开始工作。在做任何其他事情之前，创建计划文件是第一优先级。

⚡

规则 2: 2-操作规则（必读）

每完成 2 次 view/browser/search 操作后，必须立即更新 findings.md。这是保持上下文一致的铁律，不能跳过。

📓

规则 3: 记录所有错误

遇到任何错误都要记录到 task_plan.md 和 progress.md 中，包括问题原因和解决方案。这些记录帮助避免重复同样的失败。

🔄

规则 4: 永不重复失败

如果某次尝试失败，记录失败原因并尝试不同方法。同样的失败不应该出现第二次。每次都要从前面的错误中学习。

💾

规则 5: 文件优先原则

重要信息存储在文件中，而非留在上下文中。当你不确定时，把发现和决策写到文件里而不是依赖记忆。

✅

规则 6: 完成前验证

在宣布任务完成之前，检查 task_plan.md 确保所有阶段都是 complete 状态。Stop Hook 会自动进行这个检查。

⚡

规则 2: 2-操作规则（必读）

每完成 2 次 view/browser/search 操作后，必须立即更新 findings.md。这是保持上下文一致的铁律，不能跳过。

📓

规则 3: 记录所有错误

遇到任何错误都要记录到 task_plan.md 和 progress.md 中，包括问题原因和解决方案。这些记录帮助避免重复同样的失败。

🔄
