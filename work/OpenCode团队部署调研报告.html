1. 核心架构理解 Architecture

OpenCode 架构定位
OpenCode 不是 Web IDE，而是一个客户端/服务器架构的 AI Coding Agent 客户端使用方式 个人开发者主要使用方式 Web UI (浏览器) 可局域网访问，无注册/登录 Desktop (桌面端) Windows/Mac/Linux 下载安装 SDK (JS/TS) API 编程接口，供系统集成 Server Mode 无头 HTTP 服务器，团队共享
关键发现：OpenCode 没有内置的多用户认证系统

实际支持的能力

  • HTTP Basic Auth（密码保护）
  • Session 按 ID 区分（不按用户）
  • Remote Config（强制统一配置）
  • /share 分享会话链接

不支持的能力

  • 用户账号系统
  • 角色权限 / 项目隔离
  • Per-user 用量统计
  • SSO / LDAP 企业认证
核心限制：团队共享服务器 = 共享同一组 Session，没有 per-user 隔离。如果业务需要严格隔离，需要自行开发 API Gateway 中间层。
硬件要求
场景CPU内存GPU说明
仅 API Server2 核4GB不需要只跑服务器，跑模型靠远程 API
本地模型8+ 核32GB+需要用 Ollama 等本地模型时
结论：团队使用场景下 不需要 GPU。OpenCode 调用外部 LLM API（Zen / Claude / DeepSeek 等），服务器只做调度。

方案 A：Docker 单机部署（推荐最快路径）最快
# 1. 安装 Docker（已有可跳过）
# CentOS: curl -fsSL https://get.docker.com | bash
# Ubuntu: apt install docker.io

# 2. 运行 OpenCode 服务器
docker run -d \
--name opencode \
-p 4096:4096 \
-v opencode-data:/root/.local/share/opencode \
-e OPENCODE_SERVER_PASSWORD=your-team-password \
ghcr.io/anomalyco/opencode:latest \
serve --hostname 0.0.0.0 --port 4096

# 3. 验证
curl http://localhost:4096/global/health
# 期望: {"healthy":true,"version":"1.15.x}
无客户端模式（Web 直接访问）
# 服务器上运行
OPENCODE_SERVER_PASSWORD=secret opencode web --hostname 0.0.0.0 --port 4096

# 团队成员浏览器访问
http://<服务器IP>:4096
# 输入密码即可使用（无需安装客户端）
Web 模式优势：售前人员无需安装任何软件，浏览器+密码即可使用。缺点是无本地文件系统访问能力（需通过 API 挂载网络路径）。

3. Skill 分发机制 Skill Distribution

Skills 存储位置（按优先级从高到低）
项目级: .opencode/skills/<name>/SKILL.md .claude/skills/<name>/SKILL.md <- 兼容 Claude .agents/skills/<name>/SKILL.md 用户全局级: ~/.config/opencode/skills/<name>/SKILL.md <- 主要使用这个 ~/.claude/skills/<name>/SKILL.md ~/.agents/skills/<name>/SKILL.md
团队 Skill 分发方法
方法 1：共享网络目录
最快
  • 文件服务器创建共享目录
  • Windows: mklink /D
  • Mac/Linux: ln -s
  • 所有成员指向同一路径
方法 2：Git 仓库 + 脚本
最规范
  • 将 Skills 放入 Git 仓库
  • 团队每日 git pull 同步
  • 版本历史可追踪
  • 需 Git 基础知识
方法 3：.zip 手动分发
最简单
  • 打包成 zip 文件
  • 分发给同事手动解压
  • 无版本控制
  • 适合小团队初始阶段
Skill 版本控制问题
注意：OpenCode Skills 没有内置版本号机制，不支持版本号约束、自动更新检测、依赖声明。
实际建议：
- 约定命名包含日期：solution-builder-20260517/SKILL.md
- 通过共享目录最后修改时间判断是否需要更新
- 通过 Git commit hash 追踪版本
Skills 能放在腾讯文档吗？不行
方式是否可行说明
腾讯文档存储 SKILL.md不可OpenCode 只从本地文件系统读取 Skills
共享网络驱动器路径部分取决于 OS 挂载能力，Windows 需映射驱动器
HTTP URL 远程加载不可不支持，OpenCode 只读本地文件
腾讯文档存储模板/参考文档可以生成结果保存到腾讯文档，Skill 放本地目录

Session 分享机制
Session Fork (分叉) 工作流: 售前 A 创建方案初稿 -> /share 生成链接 -> 发给售前 B 售前 B Fork 该 Session -> 在 A 的基础上继续修改 -> 生成新版本方案 注意: B 能看到 A 的所有对话内容 -> 需靠制度约束（不分享敏感客户信息） -> 或每个售前人员运行自己的 OpenCode -> 用腾讯文档协作交换结果
解决多用户隔离的三个方向
方案复杂度隔离效果说明
A. 制度约束无成本依赖自觉约定不分享敏感项目，制度上禁止
B. 各自本地安装低完全隔离每人用自己的 OpenCode + API Key，结果上传腾讯文档
C. API Gateway 中间层高（需开发）技术隔离按 API Key 路由到不同 Session Namespace
推荐：初期用方案 A（制度）+ 方案 B（各自本地）的组合。方案 C 投入高，建议等业务规模大了再考虑。

最终结论
OpenCode 适合售前团队的场景:
单人使用（每人本地，共享 API Key）方案生成（Skill + LLM）文档编写（生成 Word/Excel）团队分享（/share 链接）
不适合的场景:
需要严格用户隔离的协作需要按用户计费需要 SSO/LDAP 企业认证Skills 远程托管
最快路径：今天就能用 Docker 部署一台服务器，30 分钟跑起来，1-2 小时完成第一个 Skill。真正的多用户隔离问题，可以用"制度 + 腾讯文档协作"来弥补。
