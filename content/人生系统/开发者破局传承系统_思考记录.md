## 六、待整理内容

### 第一个框架：需求分析框架

#### 框架1：需求分析框架

**【一句话定义】**
在动手写代码之前，通过系统性的提问和确认，确保自己和需求方对"做什么"和"做到什么程度"达成一致，避免做到一半需求变了、改了无数遍最后用第一版的悲剧。

**【什么时候用】**
- 业务方说"先做做看"
- 需求描述模糊，如"做一个用户中心"、"优化一下性能"
- 多人需求，不知道听谁的
- 需求经常变化，没有明确的优先级

**【核心步骤】**
1. **问目的**：你做这个是为了解决什么问题？（不要问"做什么"，要问"为什么"）
2. **问边界**：做到什么程度算成功？哪些不做？（避免无限扩展）
3. **问验收**：你怎么判断这个功能做完了？（避免做了不算）
4. **问变化**：如果做到一半需求变了，怎么办？（提前约定）
5. **问优先级**：如果时间不够，哪些可以砍掉？（避免全部要）

**【一个真实案例】**
某次业务方说"做一个会员中心"，做了两个月，做完业务方说"这不是我们要的"。
后来复盘发现：
- 当时没问"为什么要做会员中心"（实际是想解决老用户活跃问题）
- 没问"做到什么程度算成功"（以为只是展示，实际要优惠券、积分、等级）
- 没问"如果做到一半想改怎么办"（后来加了3次需求）

如果最初问清楚目的和边界，本来2周可以做完的东西，不用拖2个月。

---

#### 框架2：全局视野框架

**【一句话定义】**
无论你只是项目中多么微小的一个环节，都要清楚自己在整体中的位置和价值——不被细节淹没，知道自己在做什么、为什么做、做到什么程度算完成。

**【什么时候用】**
- 项目体量很大，你只是其中一个环节
- 感觉每天很忙，但又不知道在忙什么
- 觉得自己做的事情没有价值
- 只想写代码，不想管其他事情

**【核心步骤】**
1. **问全局**：这个项目最终是要做什么？谁会用？什么是成功的标志？
2. **问位置**：我负责的部分在整个项目中处于什么位置？上下游是谁？
3. **问价值**：我做的事情对最终用户有什么价值？如果不做会怎样？
4. **问风险**：我负责的部分可能出什么问题？谁能帮我发现？
5. **问出口**：我做完这个，后面谁接手？我怎么知道做完了？

**【一个真实案例】**
做一个电商系统后端，你负责"订单状态查询"这个接口。
- 只看自己：就是一个简单的数据库查询，加个缓存优化
- 看全局：这是用户查看订单详情的入口，直接影响转化率；订单状态是整个交易流程的核心，涉及库存、支付、发货等各个系统的数据
- 看价值：如果查询慢，用户可能放弃下单；如果状态不对，可能导致客诉

从"写一个查询接口"到"理解自己在交易流程中的位置"，这个视角转变让你：
- 知道哪些优化是重要的（缓存、分页）
- 知道哪些边界是要考虑的（状态一致性、超时处理）
- 知道出了问题该找谁（上游库存系统、下游物流系统）

#### 核心概念

**有积累的事** = 花了时间，时间会继续产生价值
**没积累的事** = 花了时间，时间过了就过了

| 有积累 | 没积累 |
|--------|--------|
| 写内容发网上 | 刷短视频 |
| 打造一个产品 | 纯粹玩游戏 |
| 建立关系网络 | 纯闲聊 |
| 学习能复用的技能 | 学了不用 |

#### 3个原则

1. **只做"复利"的事**
   - 花1小时 = 产生10小时的价值 → 复利（有积累）
   - 写小红书笔记（高复利）
   - 打磨思维框架（高复利，可用10年）

2. **先完成，再完美**
   - 不需要很厉害才开始，需要开始才能变厉害

3. **每天只做3件事**
   - 1件必须做的
   - 1件应该做的
   - 1件想做的

#### 具体时间分配（每天1小时）

```
20:00 - 20:30  发小红书/运营（30分钟）
20:30 - 21:00  写思维框架/打磨内容（30分钟）
```

### 话题C：怎么把经验传给儿子？

#### 基本情况
- 儿子年龄：8岁
- 传承目标：A) 解决问题的思维（分析方法）

#### 传给8岁儿子的方法

1. **给他讲你踩过的坑（故事化）**
   - "爸爸之前不知道问清楚要求，结果做了很多无用功"
   - "爸爸曾经以为很简单，后来发现很复杂"
   - "爸爸遇到一个问题，想了3个办法"

2. **生活中的思维训练**
   - 搭积木："你先想想要搭什么，再动手"
   - 做作业："先看看题目问的是什么，再回答"
   - 玩游戏："输赢不重要，想想下次怎么赢"

3. **你正在做的事，就是最好的传承**
   - 写思维框架 → 以后可以给儿子看
   - 发小红书 → 儿子长大能看到爸爸的思考
   - 做系统 → 以后可以交给儿子

#### 具体操作：每天10分钟

```
陪儿子做作业/玩游戏时：
1. 问他"你觉得这个问题是什么？"
2. 问他"你想怎么办？"
3. 问他"还有别的办法吗？"
4. 问他"你觉得哪个办法最好？"
```

#### 终极目标

你现在建立的"系统"：
- 你的思维框架 → 以后教给儿子
- 你的影响力 → 以后给儿子
- 你的产品/客户 → 以后可以给儿子继承

你儿子8岁，等他20岁时，你建立的系统正好成熟。他可以直接继承你的"思考方式"和"事业"。

### 本次讨论的核心内容

#### 1. 三个真正的"坑"（不是技术坑，是职业困境）

| 坑 | 表现 | 本质 |
|----|------|------|
| 需求不明确 | 做到一半需求变了，改了无数遍最后用第一版 | 被动接受别人的想法 |
| 项目体量太大 | 只是一个环节，不知道整体是什么 | 没有全局视野 |
| 写代码只是执行 | 别人想好了，你来实现 | 没有决策权 |

#### 2. 三个对应的思维框架

- **框架1：需求分析框架** —— 怎么在动手前问清楚
- **框架2：全局视野框架** —— 怎么在任何位置看到整体
- **框架3：决策思维框架** —— 怎么从执行者变成思考者
