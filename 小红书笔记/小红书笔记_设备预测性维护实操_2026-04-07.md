### 一、为什么设备会"突然"坏？

设备从来不会"突然"坏，只是你没发现征兆。

**轴承磨损的过程：**
- 第1-3个月：振动值正常，温度正常
- 第4个月：振动值开始轻微上升（肉眼看不出）
- 第5个月：振动值明显升高，温度开始上升
- 第6个月：异响、发热、最后卡死

预测性维护的本质：**在第4个月就发现异常，提前预警**。

---

### 二、需要采集哪些数据？

**核心传感器（每台设备）：**

| 传感器类型 | 型号举例 | 安装位置 | 采集频率 | 价格 |
|-----------|---------|---------|---------|------|
| 振动传感器 | PCB 352C33 | 轴承座垂直方向 | 10kHz（每秒1万次） | 800-1500元/个 |
| 温度传感器 | PT100 | 轴承座表面 | 1Hz（每秒1次） | 50-100元/个 |
| 电流传感器 | 霍尔传感器 | 电机电源线 | 100Hz | 30-50元/个 |

**为什么振动要高频采集？**
- 轴承的故障特征频率通常在500-5000Hz
- 采集频率要是故障频率的2倍以上（奈奎斯特定理）
- 所以至少要10kHz

**一个车间20台关键设备，传感器成本：**
- 振动传感器：20台 × 2个/台 × 1000元 = 4万
- 温度传感器：20台 × 1个/台 × 80元 = 1600元
- 电流传感器：20台 × 1个/台 × 40元 = 800元
- **合计：约4.3万元**

### 三、数据怎么采集和传输？

**架构设计：**

```
传感器 → 数据采集卡(DAQ) → 边缘网关 → 云服务器/本地服务器
```

**具体设备选型：**

| 层级 | 设备 | 型号举例 | 功能 | 价格 |
|-----|------|---------|------|------|
| 数据采集 | DAQ卡 | NI USB-6001 或 国产研华 | AD转换，采集模拟信号 | 3000-8000元 |
| 边缘计算 | 工业网关 | 华为、研华、东土 | 数据预处理、上传 | 2000-5000元 |
| 传输方式 | 4G/5G模块 或 工业以太网 | - | 数据传输 | 500-1500元 |
| 云平台 | 阿里云IoT/腾讯云IoT | - | 数据存储、展示 | 按量计费 |

**一个车间的采集传输成本：**
- DAQ卡：5个点位 × 5000元 = 2.5万
- 边缘网关：5台 × 3000元 = 1.5万
- 网络设备：约5000元
- **合计：约4.5万元**

### 四、数据处理：从原始数据到特征

振动数据是最复杂的，我来详细说。

**原始数据长这样：**
- 每秒1万个采样点
- 每小时3.6亿个数据点
- 直接用？不行，太多了

**处理步骤：**

**步骤1：时域特征提取**
```
从1万个点中提取：
- 有效值(RMS)：振动的平均能量
- 峰值(Peak)：最大振幅
- 峭度(Kurtosis)：冲击性指标
→ 得到3个特征值，每秒更新一次
```

**步骤2：频域分析(FFT)**
```
快速傅里叶变换：
- 把时域信号转成频域
- 找出主要频率成分
- 轴承外圈故障频率：BPFO
- 轴承内圈故障频率：BPFI
- 滚动体故障频率：BSF
→ 得到故障特征频率的幅值
```

**步骤3：趋势分析**
```
不是看某一秒的值，而是看7天趋势：
- RMS从0.5mm/s涨到0.8mm/s → 轻微异常
- 峭度从3涨到6 → 有冲击信号
- BPFO频率幅值从0.1涨到0.5 → 外圈可能磨损
```

### 五、预警模型怎么建？

**方案1：阈值报警（简单，但误报多）**

```
设置固定阈值：
- RMS > 1.0mm/s → 预警
- 温度 > 60℃ → 预警
- 电流 > 额定值120% → 预警
```

**问题：**
- 不同设备阈值不同，调参很麻烦
- 环境变化（负载、温度）会误报

---

**方案2：机器学习模型（推荐）**

**我用的是这个架构：**

```
输入特征（每台设备）：
├── RMS值（时域）
├── 峰值（时域）
├── 峭度（时域）
├── BPFO幅值（频域）
├── BPFI幅值（频域）
├── BSF幅值（频域）
├── 温度
├── 电流
└── 负载率

↓ 随机森林分类器（Random Forest）

输出：
├── 正常（绿色）
├── 轻微异常（黄色）
├── 需要关注（橙色）
└── 立即检修（红色）
```

**为什么用随机森林？**
- 不需要大量数据（几百个样本就能训练）
- 解释性强（能看出哪个特征贡献最大）
- 训练快，部署简单

**训练数据从哪来？**
- 前3个月：只采集数据，不预警（建立基线）
- 设备每次维修：记录故障类型（打标签）
- 积累100个故障样本后：训练模型

### 六、系统怎么部署？

**软件架构：**

```
数据层：
├── InfluxDB（时序数据库，存传感器原始数据）
├── PostgreSQL（存设备信息、报警记录）
└── Redis（缓存实时数据）

计算层：
├── Python脚本（特征提取、FFT计算）
├── Scikit-learn（机器学习模型）
└── 定时任务（每1分钟计算一次）

展示层：
├── Grafana（可视化大屏）
├── 移动端小程序（报警推送）
└── 短信接口（重要报警）
```

**开发成本：**
- 后端开发：2人月 × 2万 = 4万
- 前端开发：1人月 × 2万 = 2万
- 部署调试：1人月 × 2万 = 2万
- **合计：约8万元**

### 八、老板常问的3个问题

**Q1：一定要高频振动传感器吗？便宜点的行不行？**

不行。低频传感器（比如普通加速度计，采样率100Hz）采集不到轴承故障特征频率，预警准确率只有60%左右。

---

**Q2：模型准确率多高？**

我的经验：
- 阈值报警：准确率50-60%，误报多
- 机器学习模型：准确率85-90%，需要持续调优
- 深度学习（CNN/LSTM）：准确率90-95%，但需要大量数据

中小企业建议：先用随机森林，够用了。

---

**Q3：能不能直接买现成的系统？**

可以，但要看清楚：
- 很多"预测性维护系统"只是数据采集+阈值报警
- 没有故障特征提取，没有机器学习模型
- 价格还贵，动不动几十万

**我的建议：**
- 设备数量<10台：买现成SaaS服务（如阿里云工业大脑）
- 设备数量10-50台：找有工业经验的小团队定制
- 设备数量>50台：可以自建团队

---

### 总结：预测性维护落地的5个关键

1. **传感器选对**：振动至少10kHz，温度用PT100
2. **特征提取做好**：时域+频域，不是看原始数据
3. **模型选简单**：随机森林够用，别上来就深度学习
4. **数据要积累**：至少3个月基线数据
5. **持续优化**：每次误报都要分析，模型越用越准
