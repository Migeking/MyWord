## 一、技能定位

**一句话定位**：把方案人员从调研到出方案的专业能力，封装成标准化的 AI Skill，让团队里无论谁来做，输出质量都是统一的。

**核心原则**：AI **不代替人**去现场调研，而是帮助整理现场记录，输出格式统一的专业文档。

---

## 二、工作流程

```
[阶段1] 现场调研 → 方案人员到现场收集信息 → AI整理输出标准化调研报告
    ↓
[阶段2] 需求分析 → 调研报告 → 需求规格说明书
    ↓
[阶段3] 方案撰写 → 需求规格 → 可交付Word文档
    ↓
[阶段4] 清单输出 → 方案内容 → 产品清单（BOM）+ 商务清单（报价）
```

| 阶段 | 触发词 | AI输出物 | 交付格式 |
|------|--------|----------|----------|
| 阶段1 现场调研 | 「现场调研」「调研报告」「走访报告」 | 标准化调研报告 | 腾讯文档 |
| 阶段2 需求分析 | 「需求规格」「分析一下」 | 需求规格说明书 | 腾讯文档/Word |
| 阶段3 方案撰写 | 「写个方案」「技术方案」「投标方案」 | 完整方案文档 | Word/腾讯文档 |
| 阶段4 清单输出 | 「产品清单」「BOM」「投标清单」 | BOM+商务清单 | 腾讯文档表格/CSV |

## 四、使用步骤详解

### 阶段1：现场调研

**步骤1 出发前**：告诉AI「做个调研，场景是[水务泵站]」，AI加载对应行业调研清单，方案人员打印或保存到手机

**步骤2 现场走访**：携带调研清单，逐项询问用户，手填/e-mail确认关键项，拍照记录。照片命名规范：`YYYYMMDD_[项目简称]_[位置]_[序号].jpg`

**步骤3 回来后**：告诉AI「我刚做完[XX项目]的调研，信息如下：[粘贴/描述现场记录]」，AI按「现场调研报告模板」整理成标准化文档

**步骤4 交付**：AI输出腾讯文档在线报告，客户在线确认或签字，团队存档

### 阶段2：需求分析

告诉AI「基于刚才的调研报告，帮我生成需求规格说明书」，AI读取field-research-report.md内容，提取关键信息填入demand-spec-template.md，经内部评审后发客户确认

### 阶段3：方案撰写

1. 告诉AI「场景是[IoT/水务/自控]，帮我写个技术方案」
2. AI先输出方案目录，确认章节结构后再填内容
3. AI逐章节撰写，不确定参数标注「待客户确认」，不编造数据
4. 按交付Checklist自检后交付（含客户确认签字栏）

### 阶段4：清单输出

告诉AI「基于上面的方案，帮我出产品清单和商务报价」，AI按BOM模板输出腾讯文档表格，可使用配套工具计算合计金额

## 五、待补充模板清单

> 等用户发来自有模板后，按优先级逐项"蒸馏"进Skill

| 优先级 | 模板类型 | 蒸馏目标 | 状态 |
|--------|---------|---------|------|
| 高 | 现场调研报告模板 | 用户有现有模板→合并进field-research-report.md | 待用户提交 |
| 高 | 产品清单/BOM | 补充品牌偏好、产品分类习惯 | 待用户提交 |
| 高 | 技术方案模板 | 补充章节结构、常用写法 | 待用户提交 |
| 中 | 商务条款 | 补充标准付款/质保/交货期 | 待用户提交 |
| 低 | 常用产品库 | 新建product-library.md含品牌/型号/参考价 | 待用户提交 |

---

## 六、蒸馏操作步骤（收到模板后执行）

1. **读取用户模板**：上传或提供模板文件/链接，AI分析模板结构
2. **对比差异**：将用户模板与现有通用模板逐章节对比，标注差异点
3. **合并融合**：保留通用版框架，吸收用户模板特色内容，形成增强版
4. **验证输出**：用蒸馏后的模板生成真实项目文档示例，团队评审确认
5. **更新Skill**：用更新后的模板文件替换/新增到references/目录
6. **发布使用**：Skill更新后，团队全员使用同一套标准模板
