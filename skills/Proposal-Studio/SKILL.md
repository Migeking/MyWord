# solution-builder

赋能方案人员统一能力的标准化技能包。遵循**调研→分析→方案→清单**四阶段工作流，覆盖 IoT、水务、自控三大领域。

## 工作流总览

```
[阶段1] 现场调研 → 方案人员到现场收集信息 → AI整理输出标准化调研报告
    ↓
[阶段2] 需求分析 → 调研报告 → 需求规格说明书
    ↓
[阶段3] 方案撰写 → 需求规格 → 可交付Word文档
    ↓
[阶段4] 清单输出 → 方案内容 → 产品清单（BOM）+ 商务清单（报价）
```

**核心原则**：
- AI **不代替人**去现场调研
- AI **帮助整理**现场记录，输出格式统一的专业报告
- 调研报告经客户确认签字后，作为后续方案设计的法定依据

## 阶段1：现场调研与报告撰写

**重要认知**：调研是方案人员到用户现场完成的，AI 不代替人去调研。
AI 的作用是帮方案人员将现场记录整理为**标准化的调研报告**，格式统一、不漏项。

**触发词**：「现场调研」「调研报告」「填调研」「走访报告」「现场勘验」

**流程**：现场记录 → 回来后按模板填写 → 输出标准调研报告 → 后续接方案/清单

### 1.1 现场调研报告模板

调研报告的结构化模板，见 `references/field-research-report.md`

**报告包含内容**：
- 封面（项目名称/客户/日期/编号）
- 调研概要（基本信息 + 对接人 + 调研范围确认）
- 现场勘测记录（尺寸/线缆路由/环境条件）
- 附件照片清单（统一命名规范，索引现场照片）
- 现有系统/设备清单（控制系统/仪表/网络/其他）
- 现有功能描述（当前功能/问题/可利旧）
- 用户需求记录（业务需求/功能需求/特殊需求/竞争信息）
- 调研结论与建议
- 客户确认签字栏

### 1.2 调研报告输出

将收集到的现场信息按模板结构化输出为**腾讯文档在线表格**（建议用 `qclaw_tdoc_mcp_call` 写入 `smartcanvas` 格式），便于团队共享和客户在线确认。

**输出文件名**：`YYYYMMDD_[客户]_[项目]_调研报告`

### 1.3 后续动作

调研报告完成后，根据用户需求自动推进：
- 报告内部评审 → 阶段2：需求规格说明书
- 客户确认签字 → 阶段3：方案撰写
- 同步输出产品清单 → 阶段4：清单输出

### 1.4 三大行业调研清单（辅助现场使用）

调研时携带的**行业调研清单**（辅助方案人员不漏项）：

| 行业 | 调研清单 |
|------|---------|
| IoT通用 | `references/iot-research-checklist.md` |
| 水务行业 | `references/water-research-checklist.md` |
| 自控行业 | `references/autocontrol-research-checklist.md` |

> 注意：调研清单是**方案人员现场提问用的工具**，不是 AI 输出物。
> 方案人员带着清单到现场，逐项询问用户并手填/e-mail确认。
> 回来后将清单结果输入本技能，AI 整理成标准化调研报告。

## 阶段2：需求分析

**触发词**：「分析一下」「需求规格」「需求说明书」

**流程**：收集调研结果 → 拆解需求维度 → 生成需求规格说明书

### 2.1 需求维度拆解框架

无论哪个行业，从以下 6 个维度分析需求：

| 维度 | 说明 | 必问项 |
|------|------|--------|
| **1. 业务目标** | 客户想解决什么业务问题？ | 核心业务痛点 |
| **2. 现场环境** | 物理环境、网络条件、现有系统 | 安装条件、干扰源 |
| **3. 监控对象** | 要采集哪些设备/参数/信号 | 设备清单、信号类型 |
| **4. 控制要求** | 是否需要闭环控制？控制逻辑？ | 安全等级、控制精度 |
| **5. 数据要求** | 采集频率、存储周期、报表需求 | 数据量、实时性 |
| **6. 集成要求** | 是否对接现有系统？接口协议？ | 第三方系统、协议类型 |

### 2.2 生成需求规格说明书

完成调研后，生成结构化需求规格说明书（按 `references/demand-spec-template.md` 结构）。

## 阶段3：方案撰写

**触发词**：「写个方案」「出个技术方案」「帮我整理一下方案」「方案评审」

**输出**：符合行业模板的 Word 文档

### 3.1 方案结构框架

标准方案 = **背景 + 需求分析 + 方案设计 + 产品清单 + 实施规划 + 商务清单**

<details>
<summary><b>👉 点击查看：三大行业方案模板</b></summary>

| 行业 | 方案模板 |
|------|---------|
| **IoT通用** | `references/iot-proposal-template.md` |
| **水务** | `references/water-proposal-template.md` |
| **自控** | `references/autocontrol-proposal-template.md` |

</details>

### 3.2 方案撰写要求

1. **先搭框架，再填内容** — 不要上来就写，先输出目录确认结构
2. **每章必须有「推荐方案」和「备选方案」** — 除非客户明确只求最优解
3. **产品选型必须有选型理由** — 不能只写型号，要写为什么选这个
4. **不确定的参数要留空标注「待确认」** — 不要编造数据
5. **方案末尾附「客户确认签字」区块** — 避免后期歧义

## 阶段4：清单输出

**触发词**：「出个清单」「产品清单」「投标清单」「商务报价」「BOM」

### 4.1 产品清单（BOM）

根据方案选择的产品，生成标准 BOM 表。

**必须包含字段**：
- 序号 / 设备名称 / 规格型号 / 品牌 / 单位 / 数量 / 单价(¥) / 总价(¥) / 备注

**输出格式**：优先输出腾讯文档表格（`qclaw_tdoc_mcp_call`），或输出 CSV

> ⚠️ 价格来源于最近一次报价或市场参考价，须注明「参考价格，正式报价以报价单为准」

### 4.2 商务清单

在 BOM 基础上，加上商务条款：

| 项目 | 说明 |
|------|------|
| **交货期** | 合同签订后 X 周 |
| **付款方式** | 如：预付30%，到货30%，验收40% |
| **质保期** | 标准2年，或按行业惯例 |
| **技术支持** | 现场服务/远程支持/培训安排 |
| **有效期** | 报价有效期（如：30天） |

### 4.3 清单模板

完整结构见 `references/bom-template.md`

## 输出物规范

### 文档命名

```
YYYYMMDD_[行业]_[客户名称]_[文档类型]
示例：20260517_水务_XX水厂_需求调研清单.docx
     20260517_自控_XX工厂_技术方案.docx
     20260517_IoT_XX公司_产品清单.xlsx
```

### 文档质量 Checklist（交稿前必查）

- [ ] 客户名称/项目名称/日期正确
- [ ] 方案结构完整（背景→需求→方案→清单→实施→商务）
- [ ] 所有产品选型有选型理由
- [ ] 不确定参数已标注「待客户确认」
- [ ] BOM 合计金额已计算
- [ ] 商务条款已填写
- [ ] 无错别字（至少通读一遍）
